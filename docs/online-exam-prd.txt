Product Requirements Document (PRD)
Online Examination Management
Document Version: 1.0
Module: Online Examination
Primary Users: Teachers, Students, Academic Administrators
Platform: Web / Mobile
Status: Proposed
1. Purpose
The Online Examination module will provide a complete digital examination workflow that enables teachers to create, configure, conduct, and evaluate online examinations, while allowing students to securely attend examinations and submit answers electronically.
The system should support different examination types, recipient selection, academic mapping, multiple question types, question-bank-based examinations, PDF-based question papers, configurable marks, different answer submission formats, and automated/manual evaluation.
The objective is to minimize manual examination activities and provide a flexible, scalable, and user-friendly online assessment platform.

4. Exam Creation – Teacher End
The teacher should have an "Create Online Exam" option.
The exam creation process should be divided into logical steps to make the configuration easier.
Step 1 – Exam Type
The teacher should select the type of examination.
Available options:
Spot Test
Scheduled Test
4.1 Spot Test
A Spot Test is intended for an examination that students can attend immediately or within a short period.
Example:
Teacher creates a Mathematics test and makes it immediately available to the selected students.
The system should allow the teacher to configure whether students can start immediately after publishing.
4.2 Scheduled Test
A Scheduled Test should be conducted within a predefined date and time.
The teacher should specify:
Start Date
Start Time
End Date, if applicable
End Time
Exam Duration
Students should only be permitted to access the examination according to the configured schedule.

5.2 Student-wise

10. Supported Question Types
The system should support the following question types:
10.1 MCQ
Multiple Choice Question.
Example:
What is 5 × 5?
A. 10
B. 15
C. 20
D. 25
The student selects one answer.
10.2 One Word
The student provides a short one-word answer.
Example:
Who discovered gravity?
Answer:
Newton
10.3 Short Answer
The student provides a brief descriptive answer.
Example:
Explain the water cycle.
10.4 Long Answer
The student provides a detailed response.
10.5 Essay
The student provides an extended descriptive answer.
11. Question Distribution and Marks Configuration
The teacher should be able to configure how many questions should be included from each question type.
Example:
Question Type	No. of Questions	Marks/Question	Total
MCQ	10	1	10
One Word	5	1	5
Short Answer	5	2	10
Long Answer	2	5	10
Essay	1	15	15
Total	23	 	50
The system should automatically calculate:
Number of questions
Marks per question
Total marks
Maximum examination marks
The system should validate that:
Question Marks Total = Exam Total Marks
If the values do not match, the system should display an appropriate validation message.

Example:

The teacher can select the required questions.
The system should display:
Question
Question Type
Chapter
Difficulty Level, if available

Selection status

13. Random Question Selection
As an optional feature, the system may support automatic/random question selection.
Example:

This will allow teachers to create different question sets and reduce question duplication.
Possible configuration:
Manual Selection
Random Selection
14. PDF Question Paper Upload
If the teacher selects Upload PDF, the system should allow the teacher to upload a question paper in PDF format.
PDF configuration
The teacher should provide:

Total Marks

Exam Duration

Important consideration
The system should maintain the uploaded PDF as the official question paper associated with the examination.
The PDF should not be editable by students.

35. Validation Rules
The system should validate:
Exam Name is mandatory.
Exam Code must be unique.
Subject is mandatory.
Recipient selection is mandatory.
Class and division are mandatory for class-wise exams.
At least one student must be selected for student-wise exams.
Start date/time cannot conflict with configured exam rules.
Exam duration must be greater than zero.
Total marks must be greater than zero.
Pass mark cannot exceed total marks.
Required question count must be available in the question pool.
Total configured question marks must equal total exam marks.
PDF must be within the allowed file size.
Only supported file formats can be uploaded.
Students cannot access an exam outside its availability window.
Submitted exams cannot be modified by students.

39. Non-Functional Requirements

The system should support multiple students attending an examination simultaneously without significant performance degradation.
Availability

Data Integrity
Student answers must not be lost during an examination.
Scalability
The architecture should support examinations involving:
One student
One class
Multiple divisions
Multiple classes
Large student populations

41. Acceptance Criteria
The Online Examination module will be considered functionally complete when:
Teachers can create Spot and Scheduled Tests.
Teachers can assign exams class-wise or student-wise.
Teachers can select subjects and chapters.
Teachers can configure exam duration and marks.
Teachers can select questions from an existing question pool.
Teachers can upload PDF question papers.
MCQ, One Word, Short Answer, Long Answer, and Essay questions are supported.
Teachers can configure the number of questions from each question type.
Total marks are automatically calculated and validated.
Students can view eligible examinations.
Students can attend examinations within the configured time.
Students can submit text answers.
Students can upload attachments where permitted.
Answers are automatically saved.
Examination automatically submits when the timer expires.
Teachers can evaluate submitted answers.
Marks can be assigned question-wise.
Results are automatically calculated.
Teachers can publish results.
Students can view published results.
Examination and student performance reports are available.
All important examination activities are logged.

43. Overall Module Architecture
The proposed Online Examination module can therefore be structured into six major components:
1. Exam Management

Teacher creates and configures examinations.
2. Question Management

Question pool, question types, PDF question papers and question distribution.
3. Exam Delivery

Student exam interface, timer, navigation, auto-save and submission.
4. Answer Management

Text answers, attachment answers and student attempt management.
5. Evaluation & Results

Automatic/manual evaluation, marks, grades, pass/fail and result publication.
6. Reports & Analytics

Exam reports, student performance, question analysis and academic insights
